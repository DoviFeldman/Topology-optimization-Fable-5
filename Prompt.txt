## Project: STL-in → Smooth Optimized STL-out Topology Optimizer

Build a complete, working 3D topology optimization web application in **Python**. It takes a real-world STL file as input, runs a SIMP-based topology optimization, and outputs a **smooth, watertight, printable STL** with an organic, optimized look. It must run on a standard Linux VPS and also work in GitHub Codespaces or any typical Python dev environment (no GPU required, no OS-specific dependencies).

## Core Quality Bar (non-negotiable)

1. **Output smoothness is the #1 priority.** The final STL must show ZERO visible voxel/staircase artifacts. Achieve this via marching cubes on the continuous density field followed by Taubin smoothing (not plain Laplacian alone, to avoid shrinkage). The result should look like the classic "organic optimized bracket" aesthetic.
2. **Output must be watertight and manifold** — verify with trimesh (`mesh.is_watertight`) before returning it. If not watertight, repair it (fill holes, keep largest connected component, remove degenerate faces).
3. **Must handle real-world STLs**, including messy ones with up to ~1–2 million triangles. Input triangle count must not blow up memory or runtime — voxelize once, then discard the input mesh from the pipeline.
4. **Structural accuracy can be approximate.** This is for cool 3D-printed shapes, not certified engineering. Prioritize robustness, speed, and beauty over FEA precision. It should still be a real SIMP optimization (compliance minimization), not a fake filter.
5. **It must never return a broken result.** Every run on a valid closed STL must produce a printable file. Handle edge cases: non-manifold inputs (attempt repair with trimesh before voxelizing), tiny/huge models (normalize scale internally, restore original scale on export), disconnected results (keep largest connected component).

## Tech Stack (use exactly this — all pure-Python/pip installable)

- **Python 3.11+**
- **numpy**, **scipy** (sparse solvers for FEA)
- **trimesh** (STL load/save, voxelization, repair, watertight checks)

## Pipeline (implement in this exact order)

### 1. Input & Voxelization
- Accept STL upload (binary or ASCII).
- Repair with trimesh if needed (fill holes, fix normals, fix winding).
- Normalize the model to a unit bounding box internally; remember the transform to restore real-world scale on export.
- Voxelize the interior into a solid occupancy grid. Default resolution: **longest axis = 96 voxels** (configurable 48–160 via a parameter). Use `trimesh.voxel` or a ray/parity fill — must produce a *solid* fill, not just a shell.

### 2. Boundary Conditions (keep it simple and automatic, with overrides)
- Default automatic mode: fix the bottom Z-layer of occupied voxels (supports), apply a distributed downward load on the top Z-layer of occupied voxels. This gives good-looking results with zero user setup.
- Also expose optional parameters so the user can choose which face (top/bottom/left/right/front/back) is fixed and which face is loaded, and the load direction (±X, ±Y, ±Z).
- Loads/supports snap to the nearest occupied voxels of the chosen face region.

### 3. SIMP Topology Optimization (3D)
- Implement the standard 3D SIMP method (port of the well-known top3d approach):
  - 8-node hexahedral elements, linear elasticity, one global stiffness matrix assembled sparse.
  - Penalization p = 3, density filter (radius ~1.5–2.5 elements, configurable) to prevent checkerboarding.
  - Optimality Criteria update.
  - Target volume fraction configurable, default **0.35** (i.e., keep 35% of material).
  - Convergence: stop at max 60 iterations or density change < 0.01.
- Solve the linear system with `scipy.sparse.linalg` (use `cg` with a diagonal/jacobi preconditioner, or `splu` for smaller grids — pick based on DOF count).
- Only build DOFs for occupied voxels (do NOT assemble the full bounding box) — this is critical for memory on real shapes.
- Memory budget: must run within ~8 GB RAM at default resolution.

### 4. Smooth Surface Extraction (the money step — do not cut corners here)
- Optionally upsample the final density field 2× with trilinear interpolation before meshing (configurable, default on) for extra smoothness.
- Apply a light Gaussian blur (sigma ≈ 1 voxel) to the density field.
- Run marching cubes (`skimage.measure.marching_cubes`) at iso-level 0.5 on the density field.
- Apply **Taubin smoothing** (e.g., `trimesh.smoothing.filter_taubin`, ~10–30 iterations) to remove any remaining faceting without shrinking the model.
- Keep only the largest connected component.
- Verify watertight; repair if needed.
- Restore original scale/position and export binary STL.

### 5. Web App
- **FastAPI backend** with endpoints:
  - `POST /api/jobs` — upload STL + parameters (resolution, volume fraction, load/support faces, load direction). Returns a job ID. Run optimization in a background task/thread (jobs take 1–10 minutes; must not block the server).
  - `GET /api/jobs/{id}` — status + progress (current iteration / total, current compliance value, phase name like "voxelizing", "optimizing", "meshing").
  - `GET /api/jobs/{id}/result` — download the optimized STL.
  - `GET /api/jobs/{id}/preview` — the result mesh as a compact format the frontend can render (e.g., draco-free simple JSON or binary STL is fine).
- Simple in-memory job store is fine (single-user tool). Limit to 1 concurrent optimization job; queue additional ones.
- **Frontend**: one static page served by FastAPI:
  - Drag-and-drop STL upload.
  - Three.js viewer showing the input mesh, then the optimized result when done (orbit controls, nice lighting, matcap or standard material — make it look good).
  - Controls: resolution slider, volume fraction slider, dropdowns for fixed face / loaded face / load direction.
  - Live progress bar with phase + iteration count.
  - Download button for the result STL.

### 6. CLI mode (for Codespaces / headless use)
- Also provide `python optimize.py input.stl output.stl --resolution 96 --volfrac 0.35 --fix bottom --load top --dir -z`
- Same pipeline, prints progress to terminal.
